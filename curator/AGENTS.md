# curator (agent-server) rules
- Prisma: `prisma-sqlite/` (no PG features/vectors), `prisma-mariadb/` (cPanel), `prisma-postgres/` (derived from the MariaDB schema; keep models in sync, regenerate with `prisma:postgres:generate`). One engine per folder; never co-locate schemas.
- The `schema.prisma` files are the only source of database schemas. After any change run `npm --prefix curator run prisma:sql` and commit the regenerated `prisma-*/schema.sql` (a test fails when they are stale); provisioners apply them additively (`src/db/schemaSql.ts`), then partition the tables in `src/db/partitions.ts` `PARTITIONED_TABLES` by day (Postgres/MariaDB; those tables need the time column in every unique key and no foreign keys). Never hand-write DDL; MariaDB long strings need `@db.Text` / `@db.LongText` (plain `String` is VARCHAR(191)).
- Raw SQL goes through `sqlFor(prisma)` (`src/db/sqlDialect.ts`) so it runs on all three engines. New request/response/event storage code targets the `IStorageAdapter` port (`src/storage/`); see `docs/DISTRIBUTED_STORAGE_PLAN.md`.
- Sync core model changes (`Project, User, Agent, Request, Response, Conversation`, the `RequestStatus` enum and the engine tables `EventLog, BusEvent, ConversationLease, StepTrace`) with `server/prisma/schema/core.prisma` (its processor runs on that schema).
- Custom Prisma output (`src/generated/prisma-sqlite`): map `@prisma/client` in `tsconfig.json` paths.
- Execution: `CuratorRequestProcessor` runs AST nodes (`Sequence, ForEach, IfElse, Spawn, While, ToolTask`); commits context; history steps (agent, human input, tool, script) write `Response` rows, control-flow steps write `Request.output`, and every finished request goes to `StepTrace` in batches (`src/engine/StepTrace.ts`; read a step's result with `requestOutput`). No AuditLog table.
- Node dispatch: `NodeRegistry` (`src/engine/nodes/`); new handlers go in their own module using only `NodeContext` (base primitives + focused services `ctx.events`, `ctx.tools`, `ctx.calls`, `ctx.llm`; add a service rather than growing the base). Plugins contribute `nodeHandlers` (non-`Curator_` types), `services` (`provide(defineService<T>(name), impl)`, read with `ctx.service(key)`) and `maintenanceSystems`; processors also take `nodeHandlers` / `services` options. Tools run by a processor get `ctx.service` / `ctx.tryService` too; the host is `CuratorHostService` (`@curator/host`), `ctx.host` is deprecated. Poll-tick passes are ordered `MaintenanceSystem`s (`registerMaintenanceSystem`, `disabledMaintenance`).
- CLI/REPL/API: `host.runTool` / `host.emitEvent` only. Scripts stored as immutable `ScriptVersion` (ref by `scriptId`+`scriptVersion`).
- `src/cli.ts`: only `commander` at top level; `await import(...)` heavy deps inside `.action`. Run TS via `node src/cli.ts`, no tsx loader.
- Rebuild after type/contract changes: `npm --prefix curator run build`.
- Debugging prompts: what an agent actually sent to the LLM is in the LLM trace (`CURATOR_LLM_TRACE=<dir>` files, `CURATOR_LLM_TRACE_DB=1` -> `LlmCall` table), not in `Response` rows; see `docs/LLM_DEBUGGING.md`.
- Guardrails & IAM (`src/services/GuardrailService.ts`, `src/services/SecretService.ts`): All prompt-handling paths (`agentNode`) run `GuardrailService.inspectPromptIngress` (control-char stripping, truncation, regex filters, delimiter/injection checks tagged `AML.T0051`, and optional `IGuardrailProvider` / `CURATOR_GUARDRAIL_URL`). Agent-callable and MCP tools strip raw text/shell execution (`isRawExecutionTool`, `AML.T0040`), enforce Ajv JSON Schema parameter validation (`validateToolParameters`), and isolate inline VM execution (`codeGeneration: { strings: false, wasm: false }`, timeout, network-restricted by default). All model/tool egress passes through `GuardrailService.sanitizeModelOutput` (Luhn PCI-DSS PAN, SSN, cloud keys, JWTs, PEM keys, plus `SecretService.mask`); treat model output as untrusted (`escapeHtml`, `escapeShellArg`, `escapeSqlLiteral`). LLM providers validate endpoints via `GuardrailService.validateEndpointUrl` (blocking cloud metadata SSRF and enforcing `CURATOR_ALLOWED_LLM_HOSTS`). Never commit static fallback keys; use `SecretService.registerEphemeralSecret` / `ISecretVaultProvider` for scoped, short-lived agent session tokens.
